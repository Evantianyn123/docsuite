## 1. 概述

**DocSuite 文档工坊** 是运行在 **DeepSeek Harness (DSH)** 之上的文档工作台，服务对象为一名独立的水下机器人（ROV/AUV）工程师。功能域：

- **文档生成**：技术方案 / 调研报告 / 投标技术文件 / 机器人测试方案（四类文档项目，AI 生成大纲与章节）
- **知识库（KB）**：传感器/设备手册的存储、文本抽取、AI 结构化补全（型号/参数/摘要）、检索、对比、网页抓取
- **模板学习**：从历史报告归纳章节结构与写作风格（AI），支持手工模板
- **PPT 生成**：从文档项目一键生成演示文稿（16:9，pptx 导出）
- **投标辅助**：招标文件解析、应答生成、偏离分析、进度计划

**历史背景**：最初以 DSH「动态 Cordis 插件」实现（`cordis_define`/`cordis_run`），该机制**进程内生效、DSH 重启即丢失**（旧插件 docsu-1 已证实重启后消失）。因此迁移为 **DSH 安装式 link 插件**（`dsh plugin add "link:<path>"`），随 profile 持久化加载。

**当前状态**：安装式插件已正常工作——Host 路由、数据读写、AI 补全、客户端 UI 均已验证通过。

### 2.3 Profile bundle 加载机制（dsh-app-boot）

1. 读 profile `package.json` 的 `dsh.profile.bundles`（有序数组，8 项，docsuite 最后）。
2. 每个 bundle 名经 `resolveBundleDir` 解析：先 DSH 安装锚点、后 profile node_modules（两锚点机制）。
3. 每个 bundle 的 `package.json` 须声明 `dsh.bundle.patch`（指向包内 `cordis.patch.yml`），否则加载失败。
4. 组合树 = 按 bundles 顺序应用各 bundle patch + profile 自身 `cordis.patch.yml`（用户层，当前为 `[]`）+ `--patch` 覆盖。
5. `mountRootInclude` 注入自定义 `import`：裸模块名（如 `docsuite`）经 Cordis internal loader 的 `internal.import(specifier, bareModuleBaseUrl)` 解析到 bundle 的 `main`。

## 3. 插件包结构与构建系统

### 3.1 包布局

```
plugin-sources/docsuite/

├── cordis.patch.yml    # 组合树补丁：- insert: - id: docsuite / name: 'docsuite'
├── build.mjs           # 构建脚本（唯一构建入口）
├── src/
│   ├── host.js         # Host 业务源码（动态插件时代快照，1529+ 行）
│   └── client.js       # Client 业务源码（731 行）
├── lib/
│   ├── index.js        # 构建产物：Host ESM（1670 行）
│   └── client.js       # 构建产物：Client CJS factory（768 行）
└── tools/（daily 仓库归档）build-installed.mjs 等
```

### 3.2 package.json 关键字段

```jsonc
{
  "name": "docsuite",
  "type": "module",
  "main": "lib/index.js",
  "exports": {
    ".": "./lib/index.js",
    "./client": "./lib/client.js",
    "./package.json": "./package.json"
  },
  "dsh": {
    "client": {
      "inject": ["@deepseek-ai/dsh-client-runtime", "@deepseek-ai/dsh-client-ui-sidebar"],
      "platform": "web"
    },
    "bundle": { "patch": "./cordis.patch.yml" }
  },
  "peerDependencies": {
    "@deepseek-ai/cordis": "*",           // 均 optional
    "@deepseek-ai/dsh-host-webserver": "*",
    "@deepseek-ai/dsh-llm": "*"
  }
}
```

**要点**：
- `dsh.client.inject` 列出的是**必须能在 DSH node_modules 解析到的包**（运行时/类型辅助），不是服务本身；`@deepseek-ai/dsh-client-ui-slots` 不存在于 DSH，不可用。
- `exports["./client"]` 供 client-modules 提供 `/plugins/<id>/client.js`。
- `dsh.client.platform` 必须为字符串 `"web"`。

### 3.3 构建系统（build.mjs）

机械地从 `src/` 切片业务体 + 拼接骨架（**无外部依赖**）：

**Host**：
- 业务体起点：`function collectText(`；终点：最后一个 `register('docsuite/ppt/export'` 行。
- 骨架 `HOST_PRELUDE`：Node 原生兼容层（fsLocal/shellLocal/subprocessLocal/webLocal，直接 `node:fs/promises`、`node:child_process`、`node:path`、`node:os`）+ `export const name/inject/apply` + 路由注册 + dispatch。
- `HOST_CLOSE`：cleanup 生命周期（见 4.4）。

**Client**：
- 业务体起点：`const disposeCss = styles.insert(`；终点：最后一个 `slots.inject(`。
- 骨架 `CLIENT_PRELUDE`：`window.__ModuleLoader__.load({id:'docsuite', factory})` + react + CSS 注入 + fetch rpc + `exports.name/inject/apply`。

**已知构建陷阱**（模板字符串内）：
- 反斜杠需转义（`\` → `\\`，否则八进制转义 SyntaxError）。
- 正则内的 `/` 需 `\\/`。
- 文件须 UTF-8 无 BOM；PowerShell `ConvertTo-Json` 会写 BOM 导致 JSON.parse 失败（写回时用 `[System.IO.File]::WriteAllText` UTF8 无 BOM）。

## 4. Host 侧架构（进程内）

### 4.1 模块契约

```js
export const name = 'docsuite'
export const inject = ['webServer']          // 硬依赖仅 webServer
export function apply(ctx) { ... }
```

- **inject 只声明 `webServer`**。llm 用惰性解析（见 8.2），避免 llm 激活时序阻塞挂载。
- 插件运行于 DSH Node 进程内，**不在 fs-sandbox 内**（安装式 bundle 直接拥有 Node 能力）。

### 4.2 服务兼容层

动态插件时代通过 `ctx.get('fs'|'shell'|'subprocess'|'web')` 获取 DSH 服务；安装式构建用 Node 原生实现替代（保持业务代码不变）：

| 兼容层 | 实现 | 用途 |
|---|---|---|
| `fsLocal` | `node:fs/promises`（resolve/stat/readText/readBytes/writeText/listDir） | 文件读写 |
| `shellLocal` | `node:child_process.exec`（promisify） | 跑 Python / PowerShell 命令 |
| `subprocessLocal` | PATH 查找可执行文件 | python/chrome 探测 |
| `webLocal` | 全局 `fetch` | 网页抓取 |

### 4.3 路由与分发

```js
// 注册：前缀路由，handler 直操 node:http req/res
ctx.webServer.register({ kind: 'prefix', path: '/docsuite', handler: dispatch })

// 分发：/docsuite/<method> → routeHandlers Map
const method = pathname.replace(/^\//, '').replace(/\/+$/, '')   // 'docsuite/health'
const handler = routeHandlers.get(method)
// POST body 或 GET ?args= JSON.parse → handler(args) → res JSON
```

- **必须避开 `/api` 前缀**：`/api/*` 被 dsh-api-gateway 的 `connection.rpc.intercept('/api', ...)` 拦截（曾导致 404）。
- 42 个方法由 `register(method, handler)` 注册进 `routeHandlers`，`harness.handle` 兼容动态插件 API 形态。

### 4.4 生命周期（关键，曾出 bug）

```js
const cleanup = () => {
  if (disposed) return
  disposed = true
  try { if (disposeRouteFn) disposeRouteFn() } catch (e) {}
  for (const d of cleanups) { try { d() } catch (e) {} }
}
ctx.effect(() => cleanup)   // Cordis 语义：立即执行回调，返回值作销毁器
return cleanup
```

- **Cordis `ctx.effect` 会立即执行回调**，返回值作为 fiber 销毁时调用的销毁器。`ctx.effect(cleanup)`（直接传函数）会在 apply 时立刻执行 cleanup——错误写法。
- 路由销毁必须在 cleanup 内（仅 fiber 销毁时执行），不能 apply 末尾立即调用——曾导致路由注册后立刻被注销、全部 404。

### 4.5 数据目录解析

```
DOCSUITE_DATA_ROOT（环境变量）→ 否则 process.cwd()（DSH 启动目录）
rootDir = workspaceRoot + '/.docsuite-data'
```

**注意**：数据目录依赖 DSH 启动时的 cwd；从不同目录启动 DSH 会指向不同的数据目录（风险见第 12 章）。

### 4.6 Python 工具链

- 四个 Python 脚本（`ingest_file.py` 文本抽取、`export_docx.py`、`export_pptx.py`、`ocr_file.py`）以模板字符串**内嵌在 host 源码**中，首次使用时写入 `dataDir/scripts/`。
- 依赖按需 `pip install --user --no-cache-dir`（如 `pdfplumber`）。
- `ingest_file.py` 用 pdfplumber 抽取 PDF 文本到 `extracted.txt`。

## 5. Client 侧架构（浏览器内）

### 5.1 模块形态

```js
window.__ModuleLoader__.load({
  id: 'docsuite',
  factory: (require) => {
    var React = require('react')
    var el = React.createElement
    // ... 业务体（纯 React.createElement，无 JSX）...
    exports.name = 'docsuite'
    exports.inject = ['slots']
    exports.apply = function apply(ctx) { applyClient(ctx) }
    return module.exports
  }
})
```

- 执行 bundle **只注册 factory**；模块体副作用在首次 materialize 时执行（惰性 CJS）。
- `exports.inject = ['slots']`：客户端硬依赖 `slots` 服务（与 billing 插件一致）。
- 纯 JS，无 TS/JSX/import；`window.__ModuleLoader__` 由 client-modules 注入。

### 5.2 CSS 注入

```js
var styles = {
  insert: function (css, tagId) {
    var id = tagId || 'docsuite-css'
    // 若 <style data-plugin-css="docsuite-css"> 不存在则创建并挂 document.head
    return function () { /* 移除该 style 标签 */ }
  }
}
```

安装式 client **没有 styles 服务**（动态插件时代有），必须自行注入（对照 dsh-deepseek-billing 的 `lib/client.js` 模式）。曾因 stub 成空实现导致页面有文字无样式。

### 5.3 RPC 协议（客户端）

```js
function rpc(method, args) {
  // 业务体 51 处调用均传完整 method 如 'docsuite/state/summary'
  var url = method.indexOf('/') >= 0 ? '/' + method : '/docsuite/' + method
  return fetch(url, { method: 'POST', headers: {'Content-Type':'application/json'},
                      body: JSON.stringify(args === undefined ? {} : stripUndefined(args)) })
    .then(r => r.json())
}
```

- `stripUndefined` 递归剔除 undefined（含嵌套对象/数组），保证 body 是纯 JSON。
- 曾因无条件 `fetch('/docsuite/' + method)` 造成**双前缀 `/docsuite/docsuite/...`** → 前端全部 404。

### 5.4 槽位注册

```js
slots.inject('conversation.view', () => slots.register(
  { name: 'conversation.view', id: 'docsuite', order: 20, label: () => 'DocSuite' },
  () => el(DocSuiteApp, null)))
slots.inject('settings.section', () => slots.register(
  { name: 'settings.section', id: 'docsuite', order: 60, label: () => 'DocSuite' },
  () => el(SettingsContent, null)))
```

- `conversation.view` 契约仅 `{id, order, label}`（**无 icon 字段**——chat/trajectory 同样只有文字标签，属平台设计）。
- UI 结构：`DocSuiteApp`（React hooks + 内部分页 home/kb/tpl/studio/ppt/settings）。

## 6. 内部协议（HTTP）

### 6.1 通用约定

- **URL**：`POST /docsuite/<method>`（body 为 JSON）；兼容 `GET /docsuite/<method>?args=<JSON>`。
- **响应**：统一 JSON。
  - 成功：`{"ok": true, ...业务字段}`
  - 失败：`{"ok": false, "message": "中文错误说明"}`（HTTP 200）；未捕获异常 → HTTP 500 `{"ok":false,"message":...}`

## 8. LLM 集成

### 8.1 服务来源

- 服务名：**`llm`**（`@deepseek-ai/dsh-llm` 的 `LlmRuntime`，`super(ctx, "llm")`），来自 dsh-base bundle（组合树中第一个 bundle，先于 docsuite）。
- 核心 API：`llm.stream(options): AsyncIterable<StreamChunk>`、`llm.listProviders()`、`llm.listModels(provider)`。
- StreamChunk 类型：`text-delta` | `reasoning-delta` | `finish`（`finish.reason.kind` 可为 `error`/`aborted`/`stop`）。

### 8.2 惰性解析（llmResolve）

```js
let llm = null
const llmResolve = () => {
  try { const s = ctx.get('llm'); llm = s || null } catch (e) { llm = null }
  return llm
}
// 业务体：if (!llmResolve()) return {ok:false, message:'LLM 服务不可用'}
```

**原因**：profile bundles 并发挂载，llm 可能晚于 docsuite 激活；apply 时一次性 `ctx.get('llm')` 会永久捕获 undefined。

### 8.3 调用链路

```
modelRoute() 选路由:
  1. agentDefaultModel?.currentSelection()（若可用）
  2. llm.listProviders()[0] → llm.listModels(provider)[0]
  3. 无 → 返回 null → 业务返回「未找到可用模型路由」

llmText(route, system, userPrompt, maxTokens):
  llm.stream({
    provider, model,
    reasoningEffort: 'low',        // 关键：deepseek 默认 high 推理会吃光 token 预算
    temperature: 0.2,
    maxTokens: maxTokens || 16000,
    system, messages: [{ id, role:'user', content:[{type:'text',text:userPrompt}], source:{kind:'user'} }],
  })
  → 收集 text-delta 到 text、reasoning-delta 到 reasoning、finish 错误处理
  → 返回 {ok, text, reasoning}

parseModelJson(text) 容错提取 JSON（剥离 markdown 代码块/前后文字）
→ 失败自动重试一次（带纠错 prompt：「只输出 JSON」）
→ 仍失败 → 写 enrich-debug 调试文件 + 返回友好错误
```

### 8.4 已实施的预算策略

| 调用 | maxTokens |
|---|---|
| enrich / learn / gen-outline / robot-spec-draft / bid-parse | 16000 |
| enrich 重试 | 12000 |
| gen-section / gen-outline-doc / 部分重试 | 8000 |
| bid-answer | 4000 |
| 其余 | 10000 |

**原因**：deepseek 适配器 `reasoningEffort` 默认 `high`，复杂文档（如多列表格）的推理链可耗尽 9000 token 预算，流中只有 reasoning-delta、无 text-delta，JSON 解析必然失败。`low` + 上调预算后实测成功。

## 9. DSH 平台约束与机制

| 约束/机制 | 说明 | 对 DocSuite 的影响 |
|---|---|---|
| `/api/*` 拦截 | api-gateway `connection.rpc.intercept('/api', ...)` | 路由必须用 `/docsuite` 前缀（曾踩坑） |
| `webServer.register` | `{kind:'prefix'\|'exact', path, handler}`；handler 直操 node:http req/res | prefix + '/docsuite' |
| `ctx.effect` | **立即执行回调**，返回值作销毁器 | 生命周期必须 `ctx.effect(() => cleanup)` |
| `inject` 等待 | 声明硬依赖，fiber 等待服务激活 | 仅声明 webServer |
| client-modules | 扫 Loader entries 中声明 `dsh.client` 的包 → 提供 `/plugins/<id>/client.js`（no-cache） | client bundle 每请求读新文件，**改 client 只需刷新页面** |
| bundle rev | `?rev=<sha1>` 由 `rebuilt()` 更新；HMR 插件禁用时 rev 陈旧但**内容新鲜** | 刷新即得新 bundle，rev 陈旧无害 |
| `dsh.client.inject` | 必须解析到 DSH node_modules 中的包 | 用 `dsh-client-runtime` + `dsh-client-ui-sidebar` |
| slots 服务 | 客户端 `exports.inject=['slots']`；`slots.inject(slotName, () => slots.register(...))` | conversation.view / settings.section |
| 槽位契约 | conversation.view 仅 `{id, order, label}` | 无图标字段 |
| Host 改动生效 | 需重启 DSH（进程内 ESM 缓存） | 改 host → 重启 |
| workspaceRoot | `process.cwd()`（DSH 启动目录） | 数据目录随启动目录变化 |

## 12. 已知问题与风险（审核重点）

请审核 LLM 重点审查以下条目，并评估其严重性、修复建议与优先级：

### A. 架构级

1. **数据目录绑定 cwd**：`rootDir = process.cwd()/.docsuite-data`。从不同目录启动 DSH 会加载/写入**不同数据目录**（当前无 config.json，默认值即 cwd）。建议固定数据根（如环境变量常驻启动脚本或显式配置）。
2. **无并发控制**：42 个方法直接操作文件系统，多个 `gen-section`/`save-section` 并发可互相覆盖项目 JSON（同文件读-改-写无锁）。
3. **无鉴权**：`/docsuite/*` 在 3080 端口开放（DSH 默认 127.0.0.1，若暴露到局域网则无认证）。
4. **Host 无沙箱**：安装式 bundle 拥有完整 Node 能力（fs/child_process），与动态插件沙箱不同——这是平台设计还是风险，需确认。
5. **客户端双注册**：`conversation.view` + `settings.section` 均注册同名 id `docsuite`（不同槽位，语义上可接受，但需确认无槽位间状态共享问题）。

### B. 数据与质量

6. **PDF 文本抽取质量**：pdfplumber 对多列表格抽取错位（StarFish 表格值串行如 `2.0kg2.0kg 0.7kg`）；个别文件首行字符反转（`zHk054 MEO 454 - tfarcriA 2WW reetavirP 2-Y4BP` ↔ 实为 `PB4Y-2 Privateer WW2 Aircraft - 454 OEM 450kHz`）。影响 AI 补全与检索精度。
7. **base64 大文件**：上传/导出走 base64 JSON，大 PDF/pptx 内存占用高。
8. **AI 输出不稳**：`parseModelJson` 依赖模型输出 JSON 的稳定性；已用低推理强度 + 重试缓解，但复杂文档仍可能失败（有调试落盘）。

### C. 运维

9. **启动缓慢观察中**：曾反馈 DSH 加载缓慢，是否与 docsuite 相关未定论（当前注入仅 webServer，apply 内无重活；待确认是否其他 bundle 或客户端 bundle 体积导致）。
10. **bundle rev 陈旧**：HMR 插件禁用时 client rev 不更新（内容新鲜、仅缓存参数陈旧），无实际影响但可改进。
11. **构建脆弱性**：build.mjs 依赖字符串锚点切片（`function collectText(`、`const disposeCss = styles.insert(` 等），业务代码改动若触及锚点会静默生成错误产物。
12. **双源码真源**：plugin-sources 与 daily 仓库需人工同步，存在漂移风险（建议脚本化）。

### D. 安全

13. **命令注入面**：`shell.run` 拼接 `python "<script>" "<path>" "<name>"`，文件名为 `args.fileName`（仅去引号 `"`）；恶意文件名可能注入 PowerShell 命令（`ensureDir` 同样拼接）。审核应确认 Windows 下转义充分性。
14. **webSearch/webImport**：`webLocal.fetch` 抓取任意 URL，无 SSRF 防护（本地工具场景可接受，需确认）。
