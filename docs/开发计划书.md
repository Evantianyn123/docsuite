# DocSuite 水下机器人文档工坊 — 开发计划书

> 版本：v1.0（需求确认版） · 日期：2026-02
> 形态：DSH 动态 Cordis 插件原型（浏览器端页面 + Host 后端）· 个人使用

---

## 1. 项目概述

面向**水下机器人（ROV/AUV）**研发与投标场景的一体化文档工具，在 DSH 图形界面内以插件形式提供可视化工作台，覆盖：

- **四类文档的交互式生成**：技术方案、调研报告、投标技术文件、机器人测试方案
- **行业知识库**：传感器/设备说明书学习、检索、资料卡与多型号对比表
- **模板学习**：从历史报告自动归纳章节结构与文风，辅以手工模板编辑器
- **PowerPoint 生成**：调研报告/技术方案的配套 PPT（内置主题 + 自有模板，双入口）
- **多格式导出**：Word / PDF / PPTX / Markdown / HTML

## 3. 环境与平台探查结论

### 3.1 本机环境（已实测）

| 项 | 状态 | 用途 |
| --- | --- | --- |
| Python 3.14.5 | ✅ `python.exe` 可用（pip 用 `python -m pip`） | 文档解析与导出管线（python-docx / python-pptx / pypdf 等） |
| MS Office Word | ✅ 已安装 | 兜底 docx→PDF 转换（Word COM） |
| Chrome / Edge | ✅ 已安装 | HTML→PDF 无头打印（主路线，中文渲染良好） |
| pandoc / LibreOffice / wkhtmltopdf | ❌ 未安装 | 不需要，PDF 走 Chrome 打印路线 |
| Node | ✅ 已安装 | DSH Host 本身 |

### 3.2 Host 端可用服务（已通过 Inspect 确认）

- `fs` — 文件读写/目录遍历 → **数据持久化**
- `subprocess` / `shell` — 执行 Python 脚本 → **解析与导出管线**
- `web` — `search()` + `fetch()` → **网页抓取入库**
- `llm` — `stream()` 流式模型调用、adapter 注册、provider 枚举 → **插件直调生成引擎**（无需经过对话轮次，交互即时）
- `settings` — 命名空间化持久设置 → **配置中心**
- `timer` / `jobs` — 定时扫描目录、后台任务
- `harness` — `handle()` 客户端 RPC、`registerTool()` 动态工具
- Builtin：`ctx` / `harness` / `console` / `btoa` / `atob` / `TextEncoder` / `TextDecoder`

### 3.3 Client 端 UI 挂载点（已确认 Slot 树）

- **`conversation.view`（list 槽）**：会话视图 Tab 环，现有 `chat` 视图在此注册，`replaceRisk: none`。
  → **主入口：注册 "DocSuite" 视图 Tab**，与聊天 Tab 平级切换，Tab 内实现完整 SPA（导航主页 + 各分项页面）。不动任何现有 UI，风险最低、页面空间最大。
- `settings.section`（list 槽）：注册「DocSuite 设置」页。
- `sidebar.footer.action`：可选快捷入口按钮。
- `tool.view.cordis`：Run 卡片内交互区（用于首次启动引导/自检）。

## 4. 总体架构

```
┌─ Client（浏览器端）──────────────────────────────────────────────┐
│  conversation.view 新 Tab "DocSuite"（SPA）                      │
│   ├─ 导航主页（分项卡片入口）                                     │
│   ├─ 文档工坊（四类文档：大纲→逐章→Markdown 编辑预览→导出）        │
│   ├─ PPT 生成器（文档转 PPT / 独立工作流）                        │
│   ├─ 知识库（上传/扫描/录入/检索/资料卡/对比表）                  │
│   ├─ 模板库（自动学习 + 手工编辑）                                │
│   └─ 设置（数据目录/模型/主题/扫描目录）                          │
│  所有交互 → host.call('docsuite/*', args)  ←→  Blob 下载          │
└──────────────┬───────────────────────────────────────────────────┘
               │ harness.handle  Package-private RPC（JSON / base64）
┌─ Host（DSH 进程）────────────────────────────────────────────────┐
│  DocSuite 服务层（单 Plugin 演进，内部按模块分文件字符串组织）      │
│  ├─ store.js      数据层：fs 封装、JSON 读写、原子写、路径管理     │
│  ├─ rpc.js        harness.handle 统一分发                          │
│  ├─ parser.py    文本抽取：PDF/DOCX → 纯文本（Python 子进程）      │
│  ├─ indexer.js    中文分词 + 倒排索引 + 关键词检索（n-gram 起步）  │
│  ├─ kb.js         知识条目 CRUD、资料卡、对比表                    │
│  ├─ template.js   模板学习（LLM 归纳样例）与手工模板 CRUD          │
│  ├─ project.js    文档项目 CRUD、大纲/章节/引用管理                │
│  ├─ generator.js  LLM 生成：大纲/章节/应答矩阵/PPT 内容            │
│  ├─ export.js     导出编排：调 Python 生成 docx/pptx/html/pdf      │
│  ├─ web.js        网页抓取 → 清洗 → 入库                           │
│  └─ scripts/      export_docx.py / export_pptx.py / charts.py …   │
└───────────────────────────────────────────────────────────────────┘
```

### 4.1 关键架构决策

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 页面载体 | `conversation.view` 新 Tab | 不替换现有 UI（风险 none），拥有完整页面空间，与会话平级切换 |
| LLM 调用 | Host 直调 `llm.stream()` | 点击即生成，无需等待对话轮次；默认复用 DSH 已配置模型，设置页可加自定义 OpenAI 兼容 provider |
| 文档解析/导出 | Python 子进程（`subprocess`） | python-docx / python-pptx 成熟可靠；pip 依赖首启自动安装 |
| PDF | HTML → Chrome 无头打印（主）；Word COM（兜底） | 无 pandoc/LibreOffice，Chrome 中文渲染质量好 |
| 文件传输 | 上传 base64 经 RPC（大文件分块）；下载走 Blob + base64 | 动态插件 RPC 为 JSON 通道 |
| 中文检索 | Host 端轻量 n-gram 倒排起步 | 零依赖、可离线；效果不足时引入 jieba（Python） |
| OCR | PaddleOCR（懒安装，列为增强项 P2） | 模型体积大，不进 MVP |
| 代码组织 | 单 Plugin 多 Package 版本演进；函数体内模块化 | 动态代码无 bundler/import；必要时拆多 Plugin 并以 `ctx.provide` 共享服务 |

## 5. 数据模型与存储

### 5.1 数据目录（默认，可在设置中修改）

```
<数据目录>/
├── config.json          # 插件配置（与 settings 服务双向同步）
├── kb/
│   ├── index.json       # 倒排索引（可重建）
│   └── items/<id>.json  # 知识条目（资料卡）
│   └── sources/<id>/    # 原始说明书文件（pdf/docx）与抽取文本
├── templates/
│   ├── learned/<id>.json   # 自动学习的风格模型
│   └── manual/<id>.json    # 手工模板
├── projects/
│   └── <projectId>/
│       ├── meta.json        # 类型/标题/语言/模板/机型/状态
│       ├── outline.json     # 大纲树（可编辑）
│       ├── sections/<n>.md  # 逐章内容（Markdown）
│       ├── references.json  # 引用的知识条目列表
│       └── exports/         # 导出的 docx/pptx/pdf/html/md
├── scripts/             # Python 工具脚本（首次初始化时生成+装依赖）
└── terms.json           # 中英术语对照表
```

> **沙箱说明**：默认数据目录为 `%USERPROFILE%\.dsh-docsuite`（可改）。若宿主沙箱策略限制写工作区外路径，自动回退到工作区 `.docsuite-data/` 并在设置页提示切换。

### 5.2 知识库存储与检索设计（专项说明）

**决策：不引入向量数据库服务。** 纯文件 + 倒排索引为主力检索；语义检索为 M5 增强层，用「Embedding API + 本地向量文件」，依然无数据库服务。

| 对比项 | 纯文件方案（采用） | 向量数据库 |
| --- | --- | --- |
| 数据规模 | 个人使用：几十~几百份说明书，MB 级 | 为百万级向量/多用户设计，此处过度设计 |
| 依赖 | 零额外依赖 | pip + 服务 + 模型下载 |
| 持久化 | JSON 文件即持久化，可备份/迁移/diff | 数据库文件，难人工查看 |
| 升级路径 | 数据量暴涨时可平滑迁到嵌入式 Chroma | — |

**存储结构**：
```
kb/
├── meta.json            # 元数据（统计、索引版本）
├── items/<id>.json      # 资料卡（结构化参数/摘要/标签/来源）
├── sources/<id>/        # 原始 PDF/Word + extracted.txt 纯文本
├── index.json           # 倒排索引：词 → {条目id → 词频/位置/字段权重}
└── vectors.jsonl        # [M5 增强] 语义向量（可选）
```
写入只追加/更新单文件 + 增量更新倒排；索引可一键重建。

**MVP 检索（关键词全文）**：中文 2/3-gram 分词 + 停用词（效果不足引 jieba）；字段加权（标题>参数名>正文）；BM25 评分 + 分类/标签过滤 + 命中高亮。精确技术词（型号、量程、精度）检索可靠。

**M5 语义增强（无数据库）**：OpenAI 兼容 `/v1/embeddings` 生成向量（无接口则暂缓/本地小模型）；向量存 `vectors.jsonl`，内存 numpy 余弦相似度（千级向量 <10ms）；语义召回与关键词结果 RRF 融合，服务自然语言提问。

**文档联动**：逐章生成时以章标题/要点为查询词 → 关键词索引召回 Top-K → 条目摘要+出处注入上下文 → 正文插 `[出处]` 标记 → 附录汇总参考文献。

## 6. 功能模块设计

### 6.0 导航主页
- 卡片式分项入口：文档工坊 / PPT 生成器 / 知识库 / 模板库 / 设置中心
- 顶部概览：知识条目数、文档项目数、最近项目、存储占用
- 新会话打开即见，与聊天 Tab 一键切换

### 6.1 知识库（MVP 优先）
- **入库**：① 上传 PDF/Word（解析文本 + AI 生成摘要与结构化参数）② 本地文件夹扫描（设置扫描目录，手动/定时）③ 手动结构化录入（表单：分类/厂家/型号/参数表）④ 网页抓取（`web.search` → `web.fetch` → 清洗 → 确认后入库）
- **检索页（人工查阅）**：关键词全文检索 + 分类/标签/厂家过滤 + 命中高亮；结果列表 → 资料卡详情
- **资料卡**：基本参数表、说明书原文查看（内嵌页/附件）、摘要、来源追溯、编辑
- **对比表**：勾选多型号 → 生成横向参数对比表（同名参数自动对齐）→ 可导出到 Word
- **术语表**：中英对照维护，供文档生成使用

### 6.2 模板库
- **自动学习**：上传 1–N 份历史报告（docx/pdf）→ 文本抽取 → LLM 归纳章节树/文风/图表习惯/术语 → 风格模型
- **手工编辑器**：树形章节编辑（增删改/拖拽排序）、每节填写说明与字段提示、套用内置风格
- **模板应用**：生成文档时选择「自动学习模板 / 手工模板 / 空模板」，学习模板 + 手工模板可叠加

### 6.3 文档工坊（四类文档）
**通用交互流程**：
1. 新建项目：选类型 → 选模板/机型（测试类）→ 填主题与要点 → 选语言
2. **大纲生成**：LLM 生成章节树 → 树形编辑（增删/调整/批注）
3. **逐章生成**：每章独立生成 → 可「重生成/改写/精简/扩写」，支持流式输出进度
4. **Markdown 编辑预览**：页面内全文编辑 + 实时预览（手写轻量 Markdown 渲染器，支持表格/图片/代码）
5. **知识引用**：每章生成时自动检索知识库 → 正文插 `[出处]` 标记 → 附录自动生成参考文献
6. **导出**：Word / Markdown / HTML / PDF（PPT 见 6.4）

**四类差异**：
| 类型 | 特有流程 |
| --- | --- |
| 技术方案 | 标准大纲骨架；自动引用知识库设备参数作为依据 |
| 调研报告 | 支持从网页抓取资料辅助调研；一键转 PPT |
| 投标技术文件 | 上传招标文件 → 文本抽取 → LLM 提取要求清单（编号/章节/原文/类别）→ 逐条生成应答 → 生成**需求响应矩阵/偏离表**（响应/偏离/不适用）→ 汇总成文 |
| 机器人测试方案 | 按机型（ROV/AUV/通用）套用分类模板；9 大测试类别可选生成；自动生成测试矩阵表 |

**测试方案 9 大类别**：耐压与水密、推进与动力、导航与定位、通信与遥测、布放回收与作业、电池与能源、环境适应性、可靠性与耐久、安全与应急

### 6.4 PPT 生成器
- **入口一（文档一键转 PPT）**：从已完成的调研报告/技术方案抽取大纲与要点 → 生成分页 → 可逐页微调 → 导出
- **入口二（独立工作流）**：新建 PPT → 定主题 → 分页大纲 → 逐页生成（标题/要点/表格/图表）→ 预览（HTML 模拟）→ 导出
- **风格**：内置 3–5 套主题（配色/字体/版式，16:9）；支持上传自有 .pptx 作母版（python-pptx 打开模板追加页）
- **图表**：测试数据 → matplotlib 柱状/折线/雷达图（Windows 中文字体配置）→ 嵌入 PPT/Word

### 6.5 设置中心（settings.section）
- 数据目录路径（含「打开目录」）
- 模型配置：默认用 DSH 当前模型；可添加自定义 OpenAI 兼容 API（base URL / key / 模型名）
- PPT 默认主题与公司 logo（图片上传）
- 扫描目录管理（知识库文件夹扫描）
- 环境自检：Python / pip 依赖 / Chrome 可用性一键检测与安装
- 语言：界面中/英（文档语言在项目级独立选择）

## 7. 关键技术方案

| 技术点 | 方案 | 备注 |
| --- | --- | --- |
| LLM 直调 | `llm.stream()`，settings 存自定义 provider | 实施首日先查 `llm` 服务精确契约并做最小冒烟验证 |
| 文本抽取 | Python：`pypdf` + `python-docx` | 扫描件 OCR 用 PaddleOCR（P2 懒安装） |
| 中文检索 | JS n-gram 倒排 → jieba 增强 | 索引存 kb/index.json，可重建 |
| docx 导出 | `python-docx`：封面/标题层级/表格/图片/页眉页脚 | 按风格模型套样式 |
| pptx 导出 | `python-pptx`：16:9、主题色、母版复用 | 图表用 matplotlib 出 PNG |
| html/pdf | Markdown→HTML 模板；Chrome `--headless=new --print-to-pdf` | 兜底：Word COM 转 PDF |
| 图表 | `matplotlib`（中文字体：Microsoft YaHei/SimHei） | 柱状/折线/雷达 |
| 网页抓取 | `web.search` + `web.fetch` + 清洗 | 入库前用户确认（版权合规） |
| 二进制传输 | 上传：File→ArrayBuffer→base64（分块）；下载：base64→Blob | 大文件可后续改 webServer 静态路由 |
| i18n | Client 轻量文案字典；文档语言随项目 | 术语表联动 |

**Python 依赖清单**（首启自动 `python -m pip install`）：`pypdf` `python-docx` `python-pptx` `matplotlib` `beautifulsoup4`；可选：`jieba` `paddleocr` `pywin32`

## 9. 风险与对策

| 风险 | 对策 |
| --- | --- |
| `llm.stream` 契约细节未知 | M0 首日 Inspect 查精确契约 + 最小冒烟调用，失败则改用动态 Tool + 模型步骤方案 |
| Host 沙箱限制写数据目录 | 默认目录自动回退工作区 `.docsuite-data/`，设置页提示；必要时按宿主策略申请权限 |
| 动态代码无 bundler/import | 全部手写 `React.createElement` + 轻量 Markdown 渲染器；代码模块化组织在单函数体内 |
| 大文件（说明书/招标书）base64 传输慢 | 分块上传；后续 webServer 静态路由直传 |
| 中文分词/检索效果 | n-gram 起步，jieba 增强，索引可重建 |
| Python 依赖安装失败 | 环境自检页逐步诊断；依赖全部纯 Python 轮子（无编译） |
| OCR 体积大 | 懒安装（P2），MVP 支持文字版 PDF/Word |
| 代码量增长超出单 Package 承载 | 按模块拆多 Plugin，核心数据服务用 `ctx.provide` 共享 |
| LLM 生成质量不稳定 | 大纲确认制 + 逐章重生成 + 风格模型约束 + 知识引用可溯源 |
