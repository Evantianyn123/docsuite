## 0. 依据与复核结论

外部审核提出的 8 项问题全部经源码复核，**7 项属实、1 项属实且比原判更严重**：

| # | 问题 | 复核 | 关键证据 |
|---|---|---|---|
| 1 | [P0] 迁移后重启可能丢数据 | ✅ 属实 | `migrateData` 复制后立即 `Remove-Item` 删旧目录；目标目录的 config.json 启动时无人读取 |
| 2 | [P0] 路径穿越/越权文件操作 | ✅ 属实 | `readProj/deleteProject` 的 id 直接拼路径；上传 `fileName` 仅去引号 |
| 3 | [P1] 请求体/Base64 无上限 | ✅ 属实 | dispatch `Buffer.concat` 无 cap |
| 4 | [P1] HTTP 协议不可诊断 | ✅ 属实 | GET 兼容全部方法；业务错误统一 200；客户端无超时 |
| 5 | [P1] 无并发/断电安全 | ✅ 属实 | `writeJson` 直接覆盖，无原子写/锁 |
| 6 | [P1] agentDefaultModel 不一致 | ✅ 属实（且动态插件时代同样失效） | DSH 组合树**不存在** `agentDefaultModel` 服务；agent-loop 只提供 `agentLoop` |
| 7 | [P2] 本地命令执行不稳定 | ✅ **升级为 P0** | 实测: cmd.exe 默认 shell 下 `New-Item` exit 255、`Remove-Item` exit 1，均失败；**安装式插件从未成功创建过任何新目录**（目录创建时间戳全部为动态插件时代 8/30） |
| 8 | [P2] 构建/源码管理 | ✅ 属实 | 已在《总体架构与内部协议》第 11-12 章记录 |

补充复核发现:
- `customApi`（含明文 apiKey）**无任何代码使用**，可安全移除。
- Node `fs.rename` 在 Windows 可覆盖已存在文件（已实测）→ 原子写方案可行。
- `webLocal.search` 是空实现（网页搜索功能实际不可用）；`webLocal.fetch` 无 SSRF 防护。

## 1. 设计原则

1. **纵深防御**：路径安全在 Host 层统一收口，不依赖调用方自觉。
2. **失败可见**：所有被吞掉的错误改为结构化错误（`{ok:false, code, message}`），不再静默。
3. **向后兼容**：客户端与 Host 同版本升级，但 API 形状保持 `{ok, ...}` 信封，仅增加字段。
4. **最小侵入**：第一阶段不改业务功能，只加固；重构与扩展放第二、三阶段。
5. **可验证**：每条设计对应一个可执行验收测试（第 5 章）。

## 2. 第一阶段设计（阻断级，7 项）

### F1 迁移安全（P0-1）

**目标**：迁移后重启 DSH，数据必须完整恢复。

**设计**：
1. **禁止删除旧目录**；复制完成后将旧目录重命名为 `<旧目录>.migrated-<时间戳>`（保留备份，移出活动路径）。用户确认无误后可手动清理。
2. **双重 config.json 指针**：
   - 目标目录写入 `config.json`（`dataDir = 目标`）——现状保留；
   - **旧 rootDir（启动时恒为 `cwd/.docsuite-data`）也写入 `config.json`（`dataDir = 目标`）**——这是重启恢复的关键。启动时 `rootDir` 仍从 cwd 推导，但 `dataDir()` 读 `rootDir/config.json` 得到目标路径。
3. 复制改用 **Node `fs.cp(src, dst, {recursive:true})`**（替代 robocopy，绕开 shell 不确定性）。
4. 前置校验：
   - 目标不得等于/位于当前数据目录内部（防止自复制）；
   - 目标不得等于 workspaceRoot 本身（防止污染工作区根）；
   - 目标必须位于 workspaceRoot 可写范围内（沿用现有检查）。
5. 返回迁移报告：`{ok:true, dataDir, backupDir, copiedCount}`。

**改动面**：`migrateData` 重写；`fsLocal` 增加 `cp/rename/mkdir/rm`。

**验收**：迁移 → 重启 DSH → `docsuite/health.dataDir` 指向目标 → 项目/条目/模板完整。

### F2 路径安全层 + ID 校验 + 文件名净化（P0-2）

**目标**：任何用户输入（id、文件名、目录参数）都不能触及数据根之外。

**设计**：新增统一安全层（Host 顶部定义，全部文件操作改走它）：

```js
import { resolve, sep, basename, extname, dirname } from 'node:path'

// 1) 路径收口: 解析后必须仍在 root 内
function safeJoin(root, ...parts) {
  const rootNorm = resolve(String(root))
  const resolved = resolve(rootNorm, ...parts.map(String))
  if (resolved !== rootNorm && !resolved.startsWith(rootNorm + sep)) {
    const e = new Error('路径越界: ' + resolved)
    e.code = 'PATH_OUTSIDE_ROOT'
    throw e
  }
  return resolved
}

// 2) ID 严格校验（项目/条目/模板/节点）
const ID_RE = /^[a-zA-Z0-9_-]{1,64}$/
function validateId(id, label) {
  if (typeof id !== 'string' || !ID_RE.test(id)) {
    const e = new Error(label + ' 格式非法')
    e.code = 'INVALID_ID'
    throw e
  }
  return id
}

// 3) 上传文件名净化: 仅保留 basename + 扩展名白名单
const ALLOWED_UPLOAD_EXTS = ['.pdf', '.docx', '.txt', '.md', '.pptx']
function sanitizeFileName(name, allowed = ALLOWED_UPLOAD_EXTS) {
  const cleaned = String(name || '').replace(/[\u0000-\u001f]/g, '')
  const base = basename(cleaned)
  const ext = extname(base).toLowerCase()
  if (!allowed.includes(ext)) { const e = new Error('不支持的文件类型: ' + ext || '(无扩展名)'); e.code = 'BAD_FILE_TYPE'; throw e }
  if (base.length === 0 || base.length > 255) { const e = new Error('文件名非法'); e.code = 'BAD_FILE_NAME'; throw e }
  return base
}
```

**改造点**：
- `readItem/writeItem/readProj/writeProj/readTemplate/writeTemplate/deleteProject/deleteItem/deleteTemplate/listItems/listProjs/listTemplates` 全部改用 `safeJoin(await dataDir(), ...)` + `validateId`。
- `uploadItem`：`safeName = sanitizeFileName(args.fileName)`；源文件路径 `safeJoin(outdir, safeName)`。
- `migrateData` 的 `targetDir`：`safeJoin(workspaceRoot, target)` 语义校验（拒绝越界）。
- 学习模板、导出等所有构造路径处统一走 safeJoin。
- 方法入口统一捕获 `code === 'INVALID_ID'|'PATH_OUTSIDE_ROOT'|'BAD_FILE_TYPE'` → 返回 HTTP 400。

**验收**：`../`、绝对路径、非法 ID 全部返回 400，且无法访问数据根之外（含删除）。

### F3 请求体/文件大小上限（P1-3）

**目标**：超大请求不拖垮 Host，返回 413。

**设计**（dispatch 改造）：
```js
const MAX_REQUEST_BYTES = 128 * 1024 * 1024   // 请求体上限（可配置）
const MAX_UPLOAD_FILE_BYTES = 64 * 1024 * 1024 // 上传文件解码后上限
const MAX_EXPORT_FILE_BYTES = 64 * 1024 * 1024 // pptx/docx 导出上限

// dispatch 内:
if (req.headers['content-length'] > MAX_REQUEST_BYTES) { 413 }
// 流式读取, 超出即中止:
for await (const c of req) {
  chunks.push(c); total += c.length
  if (total > MAX_REQUEST_BYTES) { 413; return }
}
```
- `uploadItem`：base64 解码前检查字符串长度（`base64.length * 3/4` 估算），解码后实际字节校验，超限 413/400。
- `ppt/export`：生成 base64 后检查长度，超限返回 `{ok:false, code:'FILE_TOO_LARGE'}`。
- 413 响应：`{ok:false, code:'TOO_LARGE', message:'请求体超过上限 ...'}` + HTTP 413。

**验收**：超大请求返回 413，页面与 Host 均不卡死。

### F4 HTTP 协议改进（P1-4）

**目标**：副作用操作禁 GET；错误可诊断；客户端有超时/取消。

**设计**：

1. **方法表 + 只读白名单**（dispatch 内）：
```js
const READ_ONLY_METHODS = new Set([
  'docsuite/health', 'docsuite/config/get', 'docsuite/env/check',
  'docsuite/state/summary', 'docsuite/kb/list', 'docsuite/kb/search',
  'docsuite/kb/source', 'docsuite/kb/preview', 'docsuite/kb/compare',
  'docsuite/tpl/list', 'docsuite/proj/list', 'docsuite/proj/get',
])
// GET 请求只允许命中只读方法, 否则 405 {ok:false, code:'METHOD_NOT_ALLOWED'}
```

2. **稳定错误码**（业务失败仍 HTTP 200 + `{ok:false}`，请求级错误用真实 4xx/5xx）：

| HTTP | code | 含义 |
|---|---|---|
| 400 | `INVALID_ID` / `PATH_OUTSIDE_ROOT` / `BAD_FILE_TYPE` / `BAD_ARGS` | 输入非法 |
| 404 | `UNKNOWN_METHOD` | 未知方法 |
| 405 | `METHOD_NOT_ALLOWED` | GET 调副作用方法 |
| 413 | `TOO_LARGE` | 超限 |
| 500 | `INTERNAL` | 未捕获异常（附 message，不泄露堆栈） |
| 200 | `NOT_FOUND` / `LLM_UNAVAILABLE` / `MODEL_ROUTE_UNAVAILABLE` / `TOOLCHAIN_NOT_READY` / 业务码 | 业务失败 |

3. **requestId 链路**：客户端每次调用生成 `crypto.randomUUID()`，放 `x-docsuite-request-id` 头；服务端在响应中回显、并在 `console.error` 日志中带上；错误对象携带。

4. **客户端 rpc 改造**：
```js
function rpc(method, args, opts = {}) {
  const requestId = crypto.randomUUID()
  const ctrl = new AbortController()
  const timer = setTimeout(() => ctrl.abort(), opts.timeoutMs || 120000)
  return fetch(url, { ..., signal: ctrl.signal, headers: { ..., 'x-docsuite-request-id': requestId } })
    .then(async (r) => {
      if (!r.ok) {
        let body = null
        try { body = await r.json() } catch {}
        throw new Error((body && body.message) || ('HTTP ' + r.status))
      }
      return r.json()
    })
    .catch((e) => {
      if (e.name === 'AbortError') return { ok: false, code: 'TIMEOUT', message: '请求超时（' + (opts.timeoutMs || 120000) + 'ms），请重试' }
      return { ok: false, code: 'NETWORK', message: '网络错误: ' + e.message }
    })
    .finally(() => clearTimeout(timer))
}
```
- 所有业务调用点已用 `.then(r => r && r.ok ? ... : setErr(r.message))` 模式，`{ok:false}` 形状兼容，无需改动业务体。
- 效果：LLM 不可达/超时时，页面在限定时间内显示具体错误（验收 #5）。

**验收**：GET 删除/迁移 → 405；LLM 不可达 → 客户端 ≤120s 显示具体错误。

### F5 原子写 + 每项目写锁（P1-5）

**目标**：并发保存不互覆盖；写入中断不留下半截 JSON。

**设计**：

1. **原子写**（已实测 `fs.rename` 在 Windows 可覆盖目标）：
```js
async function writeJsonAtomic(absPath, obj) {
  await ensureDir(dirname(absPath))
  const tmp = absPath + '.tmp-' + Math.random().toString(36).slice(2, 8)
  await writeFile(tmp, JSON.stringify(obj, null, 2), 'utf8')
  await rename(tmp, absPath)   // 同盘 rename 原子替换
}
```
- 全部 `writeJson` 调用替换为 `writeJsonAtomic`。
- 断电安全边界说明：单文件写是原子的；多文件事务（如「项目+引用」）仍需第二阶段的事务层。

2. **按 key 串行写锁**（Host 内内存 Map）：
```js
const locks = new Map()
async function withLock(key, fn) {
  const prev = locks.get(key) || Promise.resolve()
  const run = prev.then(() => fn(), () => fn())
  locks.set(key, run.then(() => {}, () => {}))
  return run
}
// 用法: 所有「读-改-写」项目/条目的处理器包一层
//   withLock('proj:' + id, async () => { const p = await readProj(id); ...; await writeProj(p) })
```
- key 空间：`proj:<id>`、`item:<id>`、`tpl:<id>`、`config`、`kb:index`。
- 锁粒度：按实体，不全局，保持并发度。

3. **revision 乐观锁**（第二阶段，见 §3.2）。

**验收**：两个并发保存请求不丢数据（验收 #3）。

### F6 模型选择修正（P1-6）

**目标**：DocSuite 使用的模型可明确指定并稳定生效。

**复核结论**：DSH 组合树无 `agentDefaultModel` 服务；`ctx.get('agentDefaultModel')` 恒为 undefined，`modelRoute()` 实际**永远**退到 `llm.listProviders()[0]`（动态插件时代亦然）。审核建议的「跟随 DSH 界面切换的模型」在平台层无现成服务可依赖（agent-loop 仅暴露 `agentLoop`，未发现 currentSelection API）。

**设计（务实方案）**：
1. **移除 `agentDefaultModel` 假链路**（保留代码注释说明历史）。
2. **DocSuite 自有模型配置**：
   - config.json 的 `model` 改为 `{ mode: 'dsh', provider: '', model: '' }`（**删除 customApi**，见 F6b）。
   - 设置页新增「模型选择」：`provider` 下拉（来自 `llm.listProviders()`）+ `model` 下拉（来自 `llm.listModels(provider)`），保存到 config。
   - `modelRoute()` 优先级：`config.model.provider && config.model.model`（显式配置）→ 否则 `llm.listProviders()[0]`（现状兜底）。
3. 若后续发现 DSH 提供「当前会话模型」服务，再接入作为更高优先级。

**F6b 移除 customApi**：`DEFAULT_CONFIG` 与 config 读写中删除 `model.customApi`（含明文 apiKey）；检查无任何代码使用（已复核）→ 直接删，无需迁移逻辑。

**验收**：DocSuite 设置中切换 provider/model → 实际请求使用相同 provider/model（验收 #6）。

### F7 shell 全面替换（P2-7 → P0）

**目标**：文件操作 100% 走 Node fs；外部程序用参数数组启动。

**复核实测**：cmd.exe 默认 shell 下 `New-Item`/`Remove-Item` 必失败 → `ensureDir` 静默失效 → **安装式插件从未成功建过新目录**（新上传/模板学习/迁移目标/导出临时目录全部受影响）。

**设计**：
1. `fsLocal` 扩展：`mkdir(dir, {recursive:true})`、`rm(path, {recursive:true, force:true})`、`cp(src, dst, {recursive:true})`、`rename`。
2. 替换清单（src/host.js）：
   - `ensureDir` → `fs.mkdir`（删掉 New-Item 命令）。
   - `deleteProject/deleteItem/deleteTemplate/清理 tmp` → `fs.rm`（删掉 Remove-Item 命令）。
   - `migrateData` → `fs.cp` + `fs.rename`（见 F1）。
3. **Python 调用改 `execFile` 参数数组**（新 `runFile`）：
```js
// shellLocal 增加:
async runFile(file, args, opts = {}) {
  try {
    const { stdout, stderr } = await execFileAsync(file, args, { encoding: 'utf8', maxBuffer: 64<<20, ...opts })
    return { exitCode: 0, stdout: { text: stdout }, stderr: { text: stderr } }
  } catch (e) { return { exitCode: e.code ?? 1, stdout: { text: String(e.stdout || '') }, stderr: { text: String(e.stderr || '') } } }
}
// 调用示例:
//   shell.runFile('python', [scriptPath, uploadPath, outdir, safeName])
```
- 消除引号拼接/注入面；文件名不再进 shell 字符串。
4. `ensurePythonToolchain` 的 pip 安装同样改 `execFile` 参数数组。

**验收**：全新上传（需新建 source 目录）成功；迁移目标目录被真实创建；删除真实生效。

## 4. 第三阶段设计（稳定性）

1. **异步任务化**：LLM 生成（gen-section/gen-outline/learn）、文档解析、PPT 导出改为后台任务：
   - Host 任务注册表 `Map<taskId, {status, progress, message, cancel}>`；
   - 新端点 `docsuite/task/submit` / `task/status` / `task/cancel`；
   - 客户端轮询（或未来 SSE）显示进度，支持取消。
2. **流式传输**：上传/导出改流式（分块 base64 或 raw body 流），不再整包进内存。
3. **SSRF 防护**（webImport）：URL 校验——仅 http/https；hostname 禁止 localhost/回环/内网（127.0.0.0/8、::1、10/8、172.16/12、192.168/16、169.254/16 含 169.254.169.254、0.0.0.0）；IP 字面量与常见内网域名都拦截；注明 DNS rebinding 残余风险。
4. **冒烟测试**：构建后自动跑 `_verify.mjs` 式加载测试（import+apply+路由注册断言）+ 关键方法 mock 测试。
5. **单一源码源**：git 仓库为唯一真源，`plugin-sources/docsuite` 仅作构建产物目录；提供 `tools/sync-to-plugin.mjs` 一键同步+构建+哈希校验；提交前 CI 式检查（node --check + smoke）。

## 6. 实施顺序、工作量与风险

| 步骤 | 内容 | 预计改动 | 验证方式 |
|---|---|---|---|
| S1 | F7 shell 替换（fs mkdir/rm/cp + execFile） | host.js 多处 | 新上传/删除/迁移实测 |
| S2 | F2 路径安全层 + ID + 文件名 | host.js 全局路径点 | 越界测试 |
| S3 | F1 迁移安全重写 | migrateData | 迁移+重启实测 |
| S4 | F3 大小限制 | dispatch + upload/export | 413 测试 |
| S5 | F4 协议（方法表/错误码/requestId/客户端超时） | build.mjs dispatch + client prelude | 405/超时测试 |
| S6 | F5 原子写 + 写锁 | writeJson + 读改写点 | 并发测试 |
| S7 | F6 模型配置 + 移除 customApi | modelRoute + config + 设置页 | 模型切换测试 |

**风险**：
- 路径改造面广（~20 处），需每处过一遍，避免漏改导致新 500；
- 原子写与锁改变写入时序，需并发回归；
- build.mjs 切片锚点不变（业务体仍在 src/host.js），无构建结构变化；
- 完成后**重启 DSH** 生效（host 改动）。

**回滚**：每步独立 git commit（本地仓库），任一步异常可 revert 单步。
