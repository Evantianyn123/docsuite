## 1. 设计原则

1. 纵深防御：路径安全、配置约束、协议层校验三层独立。
2. 失败可见：所有静默错误改为结构化错误 `{ok:false, code, message}`。
3. 向后兼容：`{ok, ...}` 信封不变；协议版本以响应字段返回，暂不强拒请求。
4. 最小侵入：第一阶段只加固不扩展；重构（Repository/异步）留第二阶段。
5. 可验证：每条设计对应可执行验收（§5）。

## 2. 第一阶段设计（8 项 + 1 项防护）

### F1 迁移与数据定位器（P0-1，重设计）

**问题**：rootDir 由 `process.cwd()` 推导；把指针写在 `cwd/.docsuite-data/config.json` 里，一旦旧目录被改名或 cwd 变化，指针即丢失。

**目标**：数据位置由一个**不随数据迁移、不依赖 cwd** 的固定定位器决定。

**设计**：

```
固定位置定位器（DSH 配置目录，不受 cwd/迁移影响）:
  <DSH_HOME>/docsuite-bootstrap.json      ← { "dataDir": "<绝对路径>" }
        │ 启动时优先读取（原子写更新）
        ▼
  实际 dataDir
        ├── projects / kb / templates / scripts
        └── config.json（保留，含非路径配置；dataDir 字段仅作冗余记录，不再作为唯一依据）
```

1. **定位器路径**：`<DSH_HOME>/docsuite-bootstrap.json`（`DSH_HOME` 即 `~/.dsh`，Windows 下 `C:\Users\Evant\.dsh`）。安装式插件拥有完整 Node 权限，可写。
2. **启动解析顺序**：`bootstrap.json.dataDir`（存在且可写）→ 否则 `cwd/.docsuite-data/config.json.dataDir`（兼容旧迁移）→ 否则 `cwd/.docsuite-data`（默认）。
3. **迁移流程（四步校验）**：
   ```
   ① 复制到临时目标: fs.cp(dir, <target>.tmp-<ts>, {recursive:true})
   ② 校验: 文件数/总大小与源一致（递归比对），不一致 → 删除临时目标并中止
   ③ 原子更新定位器: 写 <DSH_HOME>/docsuite-bootstrap.json（tmp + rename）
   ④ 重启验证: 用户重启 DSH 并确认数据完整后，旧目录才允许显式清理
   ```
4. **旧目录保留策略**：迁移后旧目录**原地保留 7–14 天**（不重命名、不删除——重命名会让 cwd 指针失效）；提供「确认清理旧数据」按钮（需先通过重启验证）。
5. **禁止**：迁移目标位于当前数据目录内部 / 等于 workspaceRoot。
6. config/set 不再承担 dataDir 修改职责（见 F2）。

**验收**：迁移 → 重启（cwd 可不同）→ 数据完整；bootstrap.json 为唯一事实源。

### F2 路径安全层（P0-2，修订）

**目标**：任何输入（id/文件名/目录参数/配置路径字段）都无法越界或逃逸。

**设计**：

```js
// 1) 字符串穿越防护（safeJoin）
function safeJoin(root, ...parts) {
  const rootNorm = resolve(String(root))
  const resolved = resolve(rootNorm, ...parts.map(String))
  if (resolved !== rootNorm && !resolved.startsWith(rootNorm + sep)) {
    const e = new Error('路径越界: ' + resolved); e.code = 'PATH_OUTSIDE_ROOT'; throw e
  }
  return resolved
}

// 2) 符号链接/目录联接/重解析点防护（祖先链 realpath 校验）
async function assertNoLink(root, target) {
  let cur = target
  const seen = []
  while (cur !== root && cur.length > root.length) {
    seen.push(cur)
    cur = dirname(cur)
  }
  for (const p of seen) {
    try {
      const st = await lstat(p)
      if (st.isSymbolicLink()) { const e = new Error('路径含符号链接: ' + p); e.code = 'PATH_SYMLINK'; throw e }
    } catch (err) { if (err.code === 'PATH_SYMLINK') throw err }
    // Windows reparse point（junction）：lstat 对 junction 返回 isSymbolicLink=false，
    // 需额外 realpath 比对：realpath(p) 与 resolve(p) 不一致即视为链接/联接
    const real = await realpath(p)
    if (resolve(real) !== resolve(p)) { const e = new Error('路径含目录联接/重解析点: ' + p); e.code = 'PATH_LINK'; throw e }
  }
}

// 3) ID 严格校验 + 存量兼容
const ID_RE = /^[a-zA-Z0-9_-]{1,64}$/
function validateId(id, label) { /* 同 v1 */ }

// 4) 文件名净化（Windows 保留名/ADS/尾空格点）
const WINDOWS_RESERVED = /^(con|prn|aux|nul|com[1-9]|lpt[1-9])$/i
function sanitizeFileName(name, allowed) {
  let base = basename(String(name || '').replace(/[\u0000-\u001f]/g, ''))
  base = base.replace(/\s+$/g, '').replace(/\.+$/g, '')          // 尾空格/点
  if (base.includes(':')) { const e = new Error('文件名含非法字符(:)'); e.code = 'BAD_FILE_NAME'; throw e }  // 禁 ADS
  const stem = base.replace(/\.[^.]+$/, '')
  if (WINDOWS_RESERVED.test(stem)) { const e = new Error('Windows 保留文件名'); e.code = 'BAD_FILE_NAME'; throw e }
  const ext = extname(base).toLowerCase()
  if (!allowed.includes(ext)) { /* BAD_FILE_TYPE */ }
  if (!base.length || base.length > 255) { /* BAD_FILE_NAME */ }
  return base
}
```

**配置约束（阻断 config/set 绕过）**：
- `config/set` 改为**字段白名单**：仅允许 `language`、`pptTheme`、`model.{mode,provider,model}`、`scanDirs`。
- **禁止**通过 config/set 修改 `dataDir`/`version`（`dataDir` 只由 F1 迁移流程修改）。
- `scanDirs` 等路径字段：逐项 `safeJoin` 校验 + 必须存在 + 位于可写根内。
- **深层结构校验**：不再浅合并——`config/set` 对每个白名单字段做类型/枚举/长度校验后整体重建 config 对象。
- 迁移后的 config.json 同样只承载白名单字段（dataDir 冗余字段由迁移流程写入，config/set 无法触碰）。

**存量 ID 兼容**：实施前扫描 `kb/items`、`projects`、`templates` 全部 id，与新正则比对；若存在不匹配的历史 id，先迁移数据或放宽正则，**禁止直接启用导致历史数据不可读**。

**验收**：`../`、绝对路径、`..\..\x`、`file.txt:stream`、`CON.txt`、符号链接、junction 全部拒绝；非法 ID → 400；历史数据完整可读。

### F3 请求体/文件大小限额（P1-3，修订）

**目标**：任何单请求的内存峰值有硬上限；超限连接被干净终止。

**设计**：

| 端点/场景 | 上限 | 说明 |
|---|---|---|
| 普通 JSON 请求体 | **2 MB** | health/list/save 等全部普通方法 |
| 上传 base64 请求体 | **48 MB**（≈32 MB 解码文件） | 仅 upload/learn/bid-parse/import 走大请求 |
| 解码后文件字节 | **32 MB** | base64 解码后立即校验 |
| 导出（pptx/docx/pdf） | 生成前 `stat` 源文件/产物，**超 32 MB 拒绝**（不生成 base64） | 先检查后读取 |

**实现要点**：
- dispatch 按方法区分上限：`content-length` 预检 + 流式读取计数，超出立即**中止并排空请求流**（`req.resume()` 或 destroy），返回 413 `{ok:false, code:'TOO_LARGE'}`。
- base64 字符串长度预检（`len * 3/4 > 32MB` → 拒绝），解码后再验实际字节。
- 导出路径：`stat` 产物大小 → 超限直接 `{ok:false, code:'FILE_TOO_LARGE'}`，不进入 base64 编码。
- 中长期：上传/下载改**原始流式**（分块写入磁盘 / 文件下载），彻底移除 base64。

**验收**：>2MB 普通请求 → 413；>48MB 上传 → 413；Host 持续响应 health；连接无残留。

### F4 HTTP 协议（P1-4，修订）

**设计（v1 基础 + 细化）**：

1. **只读白名单 + GET 拒绝副作用**（同 v1）。`kb/preview`、`kb/compare` 虽只读但参数复杂，**一律 POST**（方法元数据标记 `readonly:true`，供审计/文档用）。
2. **错误码表**（同 v1）：400 系输入错误 / 404 未知方法 / 405 方法不允许 / 413 超限 / 500 未捕获 / 200 业务失败（`NOT_FOUND`、`LLM_UNAVAILABLE`、`MODEL_ROUTE_UNAVAILABLE`、`TOOLCHAIN_NOT_READY`…）。
3. **requestId**：
   - 客户端生成 `crypto.randomUUID()`，头 `x-docsuite-request-id`；
   - **服务端缺失/非法时重新生成**（非法 = 非 `^[A-Za-z0-9-]{1,64}$`），防止日志污染；
   - 响应回显 + `console.error` 日志携带。
4. **协议版本**：响应固定含 `protocolVersion: 1`；**本版不强拒请求**（Host/Client 可独立升级后再启用兼容性检查）。
5. **客户端分场景超时**（不再统一 120s）：

| 场景 | 超时 |
|---|---|
| health / config / env 探测 / 模型列表 | **8 s** |
| 列表/检索/普通读写 | **15 s** |
| 知识库补全/章节生成/大纲/模板学习/PPT | **180 s**（LLM 流式） |
| 导出 | **300 s**（大文件） |

6. **业务错误 HTTP 200 分期**：第一阶段保持 200 + `{ok:false,code}`（客户端兼容）；**第二阶段**迁移为真实 4xx/5xx + 客户端按 code 处理。

**验收**：GET 副作用 → 405；LLM 不可达 → 客户端 ≤8s（探测）/≤180s（生成）显示具体错误；requestId 回显。

### F5 原子写与并发（P1-5，重设计）

**目标**：并发「读-改-写」不丢数据；写入中断不留半截；锁不泄漏。

**设计**：

1. **原子写**（同 v1，`writeJsonAtomic`：tmp + rename；已实测 Windows 可覆盖）+ **增强**：
   - 写后 **JSON 回读校验**（`JSON.parse(read(target))` 失败 → 抛错并保留 `.bak`）；
   - 重要实体（项目/条目）写前把上一版复制为 `<file>.bak`（滚动保留 1 份）；
   - 临时文件写入失败时 `finally` 清理 `.tmp-*` 残留。

2. **写锁（不泄漏）**：
```js
const locks = new Map()
async function withLock(key, fn) {
  const prev = locks.get(key) || Promise.resolve()
  const run = prev.then(() => fn(), () => fn())
  const guard = run.then(() => {}, () => {})
  // 完成后删除自己，避免 Map 无限增长；若已有后继，则保留给后继链
  guard.finally(() => { if (locks.get(key) === guard) locks.delete(key) })
  locks.set(key, guard)
  return run
}
```
   - key：`proj:<id>` / `item:<id>` / `tpl:<id>` / `config` / `kb:index`。

3. **锁内不得执行 LLM/慢 IO**。推荐流程（覆盖 gen-section/save-section/enrich 等）：
```
锁外:  生成内容（LLM 调用、文档解析、计算）→ 得到待写字段
锁内:  重读最新实体 → 合并指定字段（不整体覆盖）→ 原子提交（rev 递增）
```

4. **正确并发验收**（替换 v1 的无效用例）：
   - 两个请求**修改同一项目不同章节**（如 section A 与 section B），并发提交；
   - 断言：最终项目 JSON **同时包含 A、B 两处修改**，且 `rev` 递增、JSON 完整可解析。

**验收**：上述并发用例通过；`.bak` 存在；无 `.tmp-*` 残留。

### F8 本地接口防护 + SSRF（P1-6 审核项，提前到第一阶段）

**目标**：Host 不接受伪造来源请求；Web 抓取不访问内网/云元数据。

**设计**：

1. **监听绑定**：确认 DSH 仅监听 loopback（`127.0.0.1:3080`）；若配置允许外部绑定，docsuite 至少校验来源。
2. **来源校验（dispatch 前置）**：
   - `Origin` 头存在时，必须为 `http://127.0.0.1:3080` 或 `http://localhost:3080`（同源）；
   - `Host` 头必须匹配监听 host:port；
   - 写操作要求 `Content-Type: application/json`。
3. **会话令牌（每次启动生成）**：
   - Host 启动时生成随机 `sessionToken`，暴露于 `docsuite/session`（一次 GET，仅当来源校验通过）；
   - 客户端首屏获取后存内存，后续请求带 `x-docsuite-token`；不匹配 → 401。
   - 目的：防跨站 POST（恶意网页无法读取 token）。
4. **webImport 暂禁**：安全实现完成前，`web/import` 返回 `{ok:false, code:'FEATURE_DISABLED'}`（UI 同步隐藏）。`web/search` 本就空实现（见 §0），一并标注禁用。
5. **SSRF（恢复 webImport 时启用）**：
   - 仅 `http/https`；
   - hostname 拒绝：localhost、回环、内网（10/8、172.16/12、192.168/16、169.254/16 含 `169.254.169.254`、0.0.0.0）、`*.internal`、裸 IP 各形式；
   - **DNS 解析后检查所有 A/AAAA**（防域名解析到内网）；**每次重定向重新解析复检**；
   - IPv4-mapped IPv6（`::ffff:x.x.x.x`）、八进制/十六进制 IP 等非常规表达全部归一化后拦截；
   - 连接/响应超时（10s）、下载大小上限（8MB）、响应流计数超限即中止。

**验收**：跨源 Origin → 403/401；无 token POST → 401；webImport 被禁；恢复后 `169.254.169.254`、内网域名、重定向到内网全部拒绝。

### F9 多文件原子性（P1-7 修订）

**事实**：逐个 rename **不是**事务；中途退出会留下「一部分新、一部分旧」。

**设计（不再声称事务）**：
1. **单文件实体**（项目/条目/模板均为单 JSON）：`writeJsonAtomic` 已保证单文件原子；「合并指定字段」在锁内完成。
2. **跨实体操作（如 enrich 写主条目 + 子条目）**：
   - 每个实体独立原子提交；中途失败 = **部分完成但每个文件均合法**（无损坏）；
   - 返回结果明示 `{ok:false, code:'PARTIAL', completed:[...]}`，客户端提示「已写入 X/Y」；
   - **第二阶段引入 WAL 事务日志**：启动时扫描未完成事务并回滚/补齐；或采用「版本化快照目录 + 原子切换 current 指针」。
3. 文档与代码注释**不再使用「事务提交」表述**。

**验收**：模拟 enrich 中途写入失败 → 已有文件均合法可解析，无半截文件。

## 3. 第二阶段设计（架构完善）

1. **Repository 层**：`kbRepo/projRepo/tplRepo/configRepo` 集中 safeJoin+原子写+锁；业务体不碰路径。
2. **revision 乐观锁**：实体 `rev` 字段；`write(proj, expectedRev)` 校验，冲突 `REVISION_CONFLICT`。
3. **协议升级**：业务错误迁移真实 4xx/5xx；`protocolVersion` 强校验（Host/Client 独立升级后启用）。
4. **WAL/快照事务**（见 F9）。
5. **移除 customApi**（F6b，第一阶段随 F6 一并处理）。
