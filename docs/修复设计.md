## 2. 第一阶段设计

### F1 迁移与数据定位器（P0-1，v3 重写）

**目标**：数据位置由固定定位器决定；迁移在任何失败点都可恢复；bootstrap 失效时**失败关闭而非静默回退**。

**定位器**：`<DSH_HOME>/docsuite-bootstrap.json`（`DSH_HOME` = `~/.dsh`，不随 cwd/数据迁移变化）。

```json
{ "dataDir": "D:\\...\\实际数据目录", "updatedAt": "ISO", "migratedFrom": null }
```

**启动解析规则（fail-closed）**：

| 情况 | 行为 |
|---|---|
| bootstrap **不存在** | 进入旧版兼容流程：读 `cwd/.docsuite-data/config.json` → 否则用 `cwd/.docsuite-data`（首次初始化） |
| bootstrap **存在且目标可访问**（目录存在、可读写） | 使用目标 |
| bootstrap **存在但目标不可访问**（磁盘离线/权限/损坏） | **失败关闭**：不创建/切换空目录；返回恢复页错误 `{code:'DATA_DIR_UNAVAILABLE', dataDir}`，提示检查磁盘与路径，提供「重新指定数据目录」入口 |

**迁移流程（全局读写门闩 + 崩溃恢复，v5）**：

```
准备阶段（目标校验，双向）:
  - target 不得位于 source 内部 / source 不得位于 target 内部 / target ≠ source
  - 第一阶段: 正式 target 必须【不存在】或【为空目录】——
    非空目标直接拒绝（TARGET_NOT_EMPTY）；「合并覆盖」不作为第一阶段功能

全局数据门闩（v5，不依赖路由名单）:
  - 迁移获取 exclusive lease（排他）；
  - 普通数据请求获取 shared/read lease；
  - 迁移期间: 除 health、migrate/status 外【所有数据端点】一律 503 DATA_MIGRATING
    ——不能只按写端点名单判断（kb/list 表面只读，内部 reconcileOrphans() 会写条目 JSON，
    复制期间调用仍可能改动源目录，破坏 SHA-256 快照一致性）；
  - 实际文件写入必须统一经过 write gate（与 shared lease 互斥）。

迁移状态文件（v5，崩溃恢复）:
  <DSH_HOME>/docsuite-migration.json
  { "operationId": "uuid", "source": "...", "staging": "...", "target": "...",
    "phase": "COPYING|VERIFIED|PUBLISHED|SWITCHED", "startedAt": "ISO" }
  每完成一步原子更新（tmp + rename）。

步骤:
① 进入维护态: 获取 exclusive lease；拒绝所有数据端点（503）→ 等待进行中读写结束
② 写状态 phase=COPYING → 复制到 staging（fs.cp recursive）
③ 校验: 相对路径清单（path+size+SHA-256）与源递归比对；不一致 → 删 staging、清状态、释放、中止
④ 写状态 phase=VERIFIED
⑤ 发布: staging 原子改名正式 target（fs.rename）；写状态 phase=PUBLISHED
⑥ 原子更新 bootstrap（tmp+rename）；写状态 phase=SWITCHED
⑦ 当前进程重新打开目标验证；失败 → 回滚 bootstrap 旧值 + 恢复内存 dataDir/rootDir/CONFIG_PATH + 报错
⑧ 清迁移状态、释放维护态（解除 503）
⑨ 重启验证: 用户重启 DSH 确认数据完整后，旧目录进入「待清理」状态

启动恢复（发现未完成迁移状态时，按 phase 处理）:
  - COPYING/VERIFIED: 清理未发布的 staging，删除状态，用旧 bootstrap（迁移未生效）
  - PUBLISHED: 对已发布 target 重新校验；校验通过 → 继续 ⑥（补更新 bootstrap）；
    失败 → 将 target 改名隔离（<target>.broken-<ts>）并恢复旧 bootstrap
  - SWITCHED: 校验 target 可用；不可用 → 同 PUBLISHED 失败分支
```

**旧目录处理**：迁移后旧目录**原地保留 7–14 天**（不重命名——重命名破坏 cwd 兼容指针）；UI 提供「确认清理旧数据」按钮（校验 bootstrap 已指向新目标且重启验证通过后才可用）。

**禁止**：迁移目标位于当前数据目录内部 / 等于 workspaceRoot / 双向包含关系（见准备阶段）。

**验收**：迁移 → 重启（cwd 可不同）→ 数据完整；staging 失败时源数据零改动；bootstrap 指向不可访问目标 → 恢复页错误而非空目录；迁移期间**所有数据端点**（含 kb/list）收到 503；在 COPYING/VERIFIED/PUBLISHED/SWITCHED 各阶段杀进程 → 重启自动恢复。

### F2 路径安全层（P0-2，v3 重写 assertNoLink）

**目标**：输入无法越界/逃逸；**同时不阻碍正常创建新文件**；Windows 语义正确。

**设计**：

```js
// 1) 字符串穿越防护 + Windows 归一化（v4: normalizeWin 可变参，v3 只取首参导致 parts 被丢弃）
function normalizeWin(...parts) {
  return resolve(...parts.map(String))
}
function safeJoin(root, ...parts) {
  const rootNorm = normalizeWin(root)
  const resolved = normalizeWin(rootNorm, ...parts)
  // 用 path.relative 判断边界（天然处理 .. 与盘符差异）
  const rel = relative(rootNorm, resolved)
  if (rel === '..' || rel.startsWith('..' + sep) || isAbsolute(rel)) {
    const e = new Error('路径越界: ' + resolved); e.code = 'PATH_OUTSIDE_ROOT'; throw e
  }
  return resolved
}

// 2) 链接/联接防护：只检查「已存在的祖先层」
async function assertNoLink(root, target) {
  // 从 target 向上找最近已存在祖先（新建文件/目录时目标本身可能不存在）
  let cursor = target
  while (true) {
    try { await access(cursor) ; break } catch (e) {
      if (e.code === 'ENOENT') { const p = dirname(cursor); if (p === cursor) break; cursor = p }
      else throw e                        // 权限等非 ENOENT 错误: 失败关闭
    }
  }
  // 对 root → cursor 之间每一层（含 cursor）做 lstat + realpath 比对
  let cur = cursor
  const chain = []
  while (cur.length >= root.length) { chain.unshift(cur); if (cur === root) break; cur = dirname(cur) }
  for (const p of chain) {
    // v4: 不捕获——链中路径已确认存在，任何 EACCES/EPERM/意外 ENOENT 都直接上抛终止操作
    const st = await lstat(p)
    if (st.isSymbolicLink()) { const e = new Error('路径含符号链接: ' + p); e.code = 'PATH_SYMLINK'; throw e }
    const real = await realpath(p)
    if (normalizeWin(real).toLowerCase() !== normalizeWin(p).toLowerCase()) {
      const e = new Error('路径含目录联接/重解析点: ' + p); e.code = 'PATH_LINK'; throw e
    }
  }
}

// 3) ID 校验 + 存量兼容（同 v2）
// 4) 文件名净化（保留名/ADS/尾空格点，同 v2）
```

**要点**：
- **正向测试**：新建项目/目录/文件（目标不存在）必须成功——assertNoLink 在目标不存在时只检查存在的祖先，不因 ENOENT 误拒。
- **失败关闭**：lstat/realpath/access 抛出 ENOENT 之外的错误（权限等）→ 直接抛错，不吞。
- **比较基准**：所有路径比较用 `path.relative` + Windows 大小写归一化（`c:\Data` 与 `C:\data` 视为同一根）。
- **配置约束**（同 v2）：config/set 字段白名单、禁改 dataDir、深层结构校验。
- **scanDirs 语义修正**：扫描来源**只需读取权限**——为 scanDirs 定义独立「授权读取根」（默认 = workspaceRoot），**不**用「可写根」约束；配置时校验目录存在且可读即可。

**验收**：`../`/绝对路径/`file.txt:stream`/`CON.txt`/符号链接/junction 全部拒绝；**新建文件与目录正常**；`c:\Data` 与 `C:\data` 同根判定；历史数据完整。

### F3 请求体/文件大小限额（P1-3，v3 修正 413 处理）

**限额表（同 v2）**：普通 JSON 2MB / 上传请求 48MB / 解码文件 32MB / 导出先 stat 超 32MB 拒绝。

**413 处理修正（顺序不可颠倒）**：
```
先发送 413 响应（writeHead + end JSON）——确保客户端收到明确错误
再处理连接:
  - 若请求体尚未读完: 有限排空（继续读取并丢弃，最多 N 字节）或
    Connection: close 头让客户端不再复用连接；
  - 不得在响应前 req.destroy()（销毁 socket 后响应无法送达）。
```
- 流式读取计数超限时：记录已读字节、立即 `writeHead(413)` + `end()`，随后 `req.resume()` 排空或置 `Connection: close`。
- 解码后文件字节校验在写入磁盘前完成（避免大文件落盘）。
- 长期：流式上传/下载替代 base64（第三阶段）。

**验收**：>2MB 普通请求 → 413 且响应可达；Host 持续响应；连接不残留。

### F5 原子写与并发（P1-5，v3 拆分 rev 语义）

**目标**：并发「读-改-写」不丢数据；写入中断不留半截；锁不泄漏。

**设计**：
1. **原子写**（同 v2）：`writeJsonAtomic`（tmp + rename）+ 写后 JSON 回读校验 + 重要实体滚动 `.bak`（保留 2 份）+ 失败时清理 `.tmp-*`。
2. **写锁不泄漏**（同 v2）：`withLock(key, fn)` 完成后自清理。
3. **锁外生成 → 锁内重读合并 → 原子提交**（同 v2）：LLM/慢 IO 在锁外；锁内只做读-合并-写。
4. **rev 语义明确拆分**：
   - **第一阶段（本阶段）**：实体引入 `rev` 字段，**每次提交递增**（读-改-写流程内自增），用于并发测试断言与审计；客户端**不携带** expectedRev。
   - **第二阶段**：客户端携带 `expectedRev`，服务端校验不匹配返回 `REVISION_CONFLICT` + 客户端刷新重试提示——真正的乐观锁。

**并发验收（有效用例）**：两请求**修改同一项目不同章节**（A、B）并发提交 → 最终 JSON 同时含 A、B 两处修改、`rev` 递增、JSON 完整、`.bak` 存在、无 `.tmp-*` 残留。

### F9 多文件原子性（P1-7，v5 补锁与原子状态）

- 单文件实体原子提交；跨实体操作（enrich 主条目+子条目）中途失败 = **部分完成但每个文件合法**，返回 `{ok:false, code:'PARTIAL', completed:[...]}`。
- **客户端补偿入口 + 幂等（v5）**：
  - **operationId 校验**：必须 `^[A-Za-z0-9-]{8,64}$`（UUID 兼容）；仅作状态文件名并走 safeJoin（防路径注入）；
  - **并发保护**：整个幂等操作包在 `withLock('op:' + operationId)` 内——两个相同 operationId 并发进入时串行执行，第二个读到的状态是第一个写好的；
  - **状态原子写**：`.ops/<operationId>.json` 用 `writeJsonAtomic`（tmp+rename）；
  - **执行计划先存**：进入操作后先保存本次解析得到的执行计划 `{plan:[{stepId, stableId, ...}]}`，再开始写实体；
  - **步骤即提交即更新**：每个实体提交后立即更新 `.ops` 状态（`completed:[...]`）；
  - **同 id 不重调 LLM**：重试时复用首次保存的解析结果（从 `.ops` 读 plan），**禁止重新调用 LLM**（否则结果变化仍可能覆盖为另一组内容——稳定 ID 只能防重复文件，不能防内容覆盖）；
  - **子实体稳定 ID**：由 `operationId + 序号` 派生（`kb_<hash(opId)>-<i>`），禁随机；
  - **TTL**：完成的 `.ops` 记录 7 天后清理；未完成记录保留（供恢复/重试）。
- 第二阶段引入 WAL/快照目录原子切换（不再逐个 rename 冒充事务）。

## 7. 清理策略（v4 去冲突）

| 产物 | 策略 |
|---|---|
| `.tmp-*`（原子写临时文件） | 写入失败立即清理；启动时扫描 dataDir 清理残留（>1 小时）——**允许自动清理** |
| `.bak`（实体备份） | 每实体滚动保留 2 份；超过 2 份删除最旧——**允许自动清理** |
| 失败的 `.staging-*` | 迁移中止后立即删除——**允许自动清理** |
| **已成功迁移的旧数据目录** | **只预警，绝不自动删除**：设置页显示占用与位置；磁盘剩余 <1GB 时仅提示用户手动清理；用户「确认清理」前再次校验该目录**不是 bootstrap 当前目标** |
| 磁盘预警 | 数据目录总大小 > 10GB 时设置页预警（后续可配置） |
